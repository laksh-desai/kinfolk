# Defect verification

Each item is a real, observed failure in the product being replaced (`docs/SPEC.md` §6).
Mark done only with a test name, a file path, or a one-line design reason that makes the
defect structurally impossible. "N/A" needs a justification.

Status: ☑ verified · ◐ partly verified (evidence so far + what is still unproven) · ☐ not yet

| 1 | Route state lost on refresh | ◐ | Every screen so far is a URL route (`apps/web/src/routes/routes.tsx`), including the selected person and every person screen: `people/:id/{add,add/:relation,edit,relationships,merge/:other}`, `compare?a&b`, `needs-detail`. RTL renders each straight from its URL, e.g. `EditPersonRoute.test.tsx` › "says \"Edit\" and whose details, restores from the URL…" and `TreeRoute.test.tsx` › "compares two people both ways…". e2e `relatives.spec.ts` reloads on the relationships screen and gets the same screen and data back; `canvas.spec.ts` › "selection survives a hard refresh and a pasted URL"; `auth.spec.ts` survives reload mid-reset. **Unproven:** dashboard and list view (M7), review (M9). |
